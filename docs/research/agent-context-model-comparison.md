# Agent Context Model Comparison: Codex, Hermes, and Pi

Research snapshot: 2026-08-09. Sources are limited to official documentation and official repository source. Hermes source was inspected at [`daabb2d`](https://github.com/NousResearch/hermes-agent/tree/daabb2d445d4b3d00da16c5c9b7ffd48768ef499), Pi at [`4181f66`](https://github.com/earendil-works/pi/tree/4181f66e6b3ccbef760c2966ecd8b596b926fec6), and pi-chat at [`9adbd29`](https://github.com/earendil-works/pi-chat/tree/9adbd29b40ee27ff1decf0fc87cbe180b40924f5).

Evidence labels used below:

- **Documented**: stated directly in official user-facing documentation.
- **Source-verified**: confirmed in official source at the pinned revision.
- **Inference**: a bounded conclusion from documented/source behavior, not an explicit product guarantee.
- **Unknown**: the reviewed official sources do not establish the behavior.

ScopeGuard's `Workspace`, `Agent`, `Conversation`, `Task`, `Artifact`, and `Handoff` terms are not treated as synonyms for similarly named concepts in these projects.

## Pi Status Caveat

The Pi repository contains two materially different layers. The released coding agent still uses its v3 `SessionManager`: cwd-keyed JSONL trees with working resume, branching, and compaction ([session types and version](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/src/core/session-manager.ts#L30-L103), [context reconstruction](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/src/core/session-manager.ts#L410-L480)). The newer lane-based `AgentHarness` and v4 session repositories are an in-progress API: the changelog calls it a "compile-complete scaffold" with unfinished operations, and current `prompt`, `compact`, `resume`, and related methods throw `HarnessNotImplemented` ([changelog](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/CHANGELOG.md#L123-L156), [implementation](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/agent/src/harness/agent-harness.ts#L347-L385)). Unless noted as **Design**, "Pi" below means the working coding-agent behavior plus the official pi-chat extension.

## Comparison

### 1. Project and workspace boundary

- **Codex - Documented:** A ChatGPT Project shares files, project instructions, and connected sources, while separate chats are recommended for distinct outcomes ([Projects](https://learn.chatgpt.com/docs/projects)). For coding runs, layered `AGENTS.md` files provide project guidance on each run ([AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)). These are context scopes, not evidence of an authorization boundary.
- **Hermes - Documented:** A profile is the persistent agent-state boundary: config, credentials, identity, memory, sessions, skills, jobs, and `state.db` are profile-local. A workspace is only the working directory; profiles do not sandbox filesystem access ([profiles](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/profiles.md#L5-L15), [profiles vs workspace](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/profiles.md#L129-L153)). Project instructions are discovered from the cwd and layered through `AGENTS.md`; subdirectory guidance can be injected progressively ([context files](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/context-files.md#L9-L64)).
- **Pi - Documented:** The cwd selects project context and the default session directory. Global plus ancestor/current-directory `AGENTS.md` or `CLAUDE.md` files layer into the prompt ([usage](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/usage.md#L75-L108)). Project trust controls loading executable project resources, but it is not a sandbox; base Pi runs with the launching user's permissions ([security](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/security.md#L3-L37)). **pi-chat - Documented:** each channel instead gets a Gondolin micro-VM, channel `/workspace`, and account `/shared` mount ([README](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L29-L40), [VM layout](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L98-L135)).

### 2. Conversation and session persistence

- **Codex - Documented:** Saved chats can be resumed; separate chats are intended for distinct outcomes inside a Project ([Projects](https://learn.chatgpt.com/docs/projects)).
- **Hermes - Documented:** Every CLI or messaging conversation is stored in profile-local SQLite with metadata, system-prompt snapshot, full role-aware messages, tool calls/results, token counts, and timestamps. CLI sessions can resume by latest, title, or ID and restore their recorded working directory ([sessions](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L9-L27), [resume](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L100-L176)). Gateway session keys determine whether a DM, user-in-group, or thread shares a transcript ([gateway keys](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L640-L671)).
- **Pi - Documented/Source-verified:** Sessions auto-save as cwd-organized JSONL trees; users can continue, resume, fork, clone, branch in place, or run ephemerally with `--no-session` ([sessions](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/sessions.md#L1-L35), [tree behavior](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/sessions.md#L69-L139)). pi-chat gives each channel worker a dedicated session directory and resumes its latest session; a separate channel log remains durable ([worker source](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L353-L375), [storage layout](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L98-L121)).

### 3. Long-term memory

- **Codex - Documented:** Local Codex memories are generated local state, separate from checked-in guidance, and optional per chat. Required guidance should remain in `AGENTS.md` or repository documentation ([Memories](https://learn.chatgpt.com/docs/customization/memories), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).
- **Hermes - Documented:** `MEMORY.md` and `USER.md` are bounded profile-local stores injected as a frozen system-prompt snapshot at session start. Writes persist immediately but enter prompt context only in a later session; capacity overflow fails instead of silently dropping entries ([memory](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/memory.md#L7-L33), [snapshot behavior](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/memory.md#L36-L67)). Users can require approval for foreground and background memory writes or disable memory ([write approval](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/memory.md#L231-L268)). Optional external providers add cross-session retrieval and synchronization; only one provider is active at a time and built-in memory remains active ([providers](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/memory-providers.md#L7-L39)).
- **Pi - Inference/Unknown:** The base coding-agent documentation establishes sessions, context files, and extension points but no first-class, cross-session long-term-memory contract. This does not prove that an installation lacks extension-provided memory. **pi-chat - Documented/Source-verified:** account `/shared/memory.md` and channel `/workspace/memory.md` are read and injected on each remote turn; the prompt instructs the agent to write durable facts there when asked ([README](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L139-L148), [injection source](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L528-L543), [per-turn hook](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L1371-L1393)). **Unknown:** the official pi-chat sources reviewed do not specify item-level provenance, size bounds, conflict resolution, retention, write approval, or ACLs inside these Markdown files.

### 4. Context compaction

- **Codex - Unknown:** The supplied official Codex sources do not document the compaction algorithm, trigger, persistence representation, or user controls. No implementation behavior is inferred here.
- **Hermes - Documented/Source-verified:** The default compressor uses lossy summarization, preserves configured head/tail context, and supports automatic thresholds plus manual `/compress`. Current configuration and source default to in-place compaction: the session ID remains stable and prior rows are soft-archived but searchable/recoverable ([configuration](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/configuration.md#L775-L840), [source default](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/hermes_cli/config_defaults.py#L756-L771)). The structured summary is iteratively updated across compactions ([algorithm](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/developer-guide/context-compression-and-caching.md#L265-L358)). **Document conflict:** the sessions page still says compression creates numbered continuation sessions ([sessions page](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L284-L292)); current config/source establishes that as legacy behavior available with `in_place: false`, not the default.
- **Pi - Documented/Source-verified:** Working v3 compaction triggers automatically near the context limit or manually with `/compact`, appends a summary entry, and rebuilds active model context from the summary plus a retained recent tail. Original tree entries remain in the JSONL history ([compaction](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/compaction.md#L25-L79), [context projection](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/src/core/session-manager.ts#L410-L469)). Branch navigation can optionally summarize the abandoned path ([branch summaries](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/compaction.md#L148-L185)). pi-chat exposes remote `compact` by calling Pi's compaction API ([source](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L703-L728)). **Design, not shipped:** lane-based `AgentHarness.compact()` is currently unimplemented.

### 5. Cross-session sharing

- **Codex - Documented:** Chats in a Project share project files, instructions, and connected sources, not one undifferentiated conversation. Optional local memory is a separate channel of generated state ([Projects](https://learn.chatgpt.com/docs/projects), [Memories](https://learn.chatgpt.com/docs/customization/memories)).
- **Hermes - Documented:** Within a profile, memory is injected into new sessions and `session_search` can retrieve actual messages across all stored sessions without summarizing them ([session search](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L570-L638)). Profiles isolate built-in memory and history; agents needing cross-profile memory are directed to external providers ([profiles](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/profiles.md#L5-L15)). Group transcript sharing is configurable and defaults to per-user isolation for groups/channels, while threads default to shared sessions ([gateway sessions](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L640-L671)).
- **Pi - Inference/Documented:** Base Pi shares filesystem context files and global/project resources across applicable sessions but does not document automatic cross-session transcript recall. pi-chat explicitly shares account memory/files across channels while retaining channel-local memory/workspace. Its `chat_history` tool searches only the current connected channel log ([memory scopes](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L98-L148), [history tool](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L917-L987)).

### 6. Subagent and multi-agent behavior

- **Codex - Documented:** Subagents run in separate threads and return summaries/results to the main chat ([Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)). The supplied source does not establish durable child execution, shared memory, or shared transcript semantics, so those are **unknown** here.
- **Hermes - Documented:** `delegate_task` creates fresh child conversations with only explicit `goal` and `context`; only final summaries enter the parent context ([delegation](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/delegation.md#L7-L57)). Children inherit enabled toolsets but cannot widen them; leaf children cannot write shared memory, message users, schedule jobs, or delegate further by default ([capabilities](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/delegation.md#L143-L167)). Background completion delivery is durable, but execution does not resume after a process crash and becomes `unknown` when effects cannot be proven ([durability](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/delegation.md#L326-L350)).
- **Pi - Documented:** Base Pi intentionally has no built-in subagents; they are extension/package territory ([design principles](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/usage.md#L299-L304)). The official example extension starts isolated `pi` subprocesses with `--no-session`, an explicit task/system prompt, selected tools/model, and a chosen cwd, then returns child output to the parent ([example](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/examples/extensions/subagent/README.md#L1-L12), [spawn source](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/examples/extensions/subagent/index.ts#L267-L339)). **Design, not shipped:** the lane design allows parallel positions over one shared session tree, but explicitly says the harness has no subagent tool; applications may use a lane or isolated fork ([design](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/agent/docs/harness-v2.md#L3876-L3896)). pi-chat runs one worker/session per channel and exposes worker status, not a documented task-delegation protocol ([README](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L65-L81)).

### 7. User control

- **Codex - Documented:** Users choose Project resources, keep outcomes in separate resumable chats, opt into local memory per chat, and place mandatory guidance in reviewable project files. Subagent results return to the main chat ([Projects](https://learn.chatgpt.com/docs/projects), [Memories](https://learn.chatgpt.com/docs/customization/memories), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)). **Unknown:** the supplied sources do not define compaction inspection or rollback controls.
- **Hermes - Documented:** Users can create/resume/name/search/export/archive/delete sessions, configure shared versus isolated gateway sessions, select/disable external memory, require memory-write approval, configure compaction, and inspect/kill/pause/steer subagents ([session management](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/sessions.md#L301-L437), [memory approval](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/memory.md#L243-L268), [agent controls](https://github.com/NousResearch/hermes-agent/blob/daabb2d445d4b3d00da16c5c9b7ffd48768ef499/website/docs/user-guide/features/delegation.md#L245-L288)).
- **Pi - Documented:** Users can disable persistence, resume/fork/clone/navigate session trees, choose whether abandoned branches are summarized, manually compact with focus instructions, disable context-file loading, and approve or reject executable project resources ([sessions](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/sessions.md#L22-L50), [project trust](https://github.com/earendil-works/pi/blob/4181f66e6b3ccbef760c2966ecd8b596b926fec6/packages/coding-agent/docs/security.md#L5-L35)). Base Pi intentionally has no permission popups or built-in sandbox. pi-chat adds remote `stop`, `status`, `compact`, and `new`; `new` starts a child-linked Pi session while keeping the channel connection ([remote commands](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/README.md#L65-L95), [new-session source](https://github.com/earendil-works/pi-chat/blob/9adbd29b40ee27ff1decf0fc87cbe180b40924f5/index.ts#L1272-L1283)).

## Implications for ScopeGuard's Enterprise-Office Memory Model

These are implications and unresolved design questions, not product decisions:

1. **Keep state categories separate.** All three systems distinguish, explicitly or implicitly, between durable transcript, active model context, curated memory, project knowledge, and artifacts. ScopeGuard can model those as separate governed objects instead of one generic "memory" store.
2. **Make scope and promotion explicit.** Hermes profile memory and pi-chat account/channel files show the risk of broad ambient sharing. ScopeGuard's private Workspace default and explicit Handoff suggest asking whether every memory item needs an owner, source Conversation, allowed audience, destination scope, and deliberate promotion event.
3. **Treat compaction as a projection, not deletion.** Hermes and Pi retain searchable/history records while replacing active context with summaries. ScopeGuard can evaluate whether compaction summaries should be versioned Artifacts with provenance, coverage boundaries, model/config metadata, and a route back to source evidence.
4. **Separate continuity from authority.** A recalled message or generated summary may help continue work but should not automatically become authoritative organizational knowledge. ScopeGuard can define which sources are advisory, verified, expired, superseded, or unavailable.
5. **Make Agent and Conversation identity durable.** External systems often bind state to a profile, cwd, channel, or session. ScopeGuard's model instead raises the question of which state belongs to the Agent, Workspace, Conversation, Member, or Organization, and which survives a Model change.
6. **Use explicit context packages for delegation.** Codex and Hermes return child summaries; Pi's example launches isolated children. ScopeGuard can evaluate whether a subagent receives a typed, reviewable Handoff containing selected instructions, evidence, Artifacts, tools, authority, and expiry rather than ambient parent memory or a full transcript.
7. **Do not conflate shared rooms with shared context.** Hermes makes per-user versus room/thread transcript sharing configurable; pi-chat separates account and channel state. ScopeGuard can require an explicit policy for collaborative Conversations instead of inferring sharing from membership in the same office channel.
8. **Expose governance controls at the same level as persistence.** Candidate controls include inspect/edit/delete/export, retention, write approval, provenance, scope changes, compaction review, subagent cancellation, and fail-closed handling for unknown child outcomes. Which controls belong to Members versus Administrators remains a product-policy question.
