# Migrating From v0.4 To Desktop v2

## Why This Is A Rewrite

v0.4 modeled ScopeGuard as a task planning and delivery system:

```text
plan -> task -> queue -> claim -> execute -> review
```

Desktop v2 models ScopeGuard as a local multi-Agent workspace:

```text
Project -> AgentProfile -> Thread -> Run
                   \-> explicit Project Context revisions
```

These models have different ownership, persistence, security, and interaction
boundaries. Reusing the v0.4 server and queue would retain coupling without
preserving useful behavior, so the obsolete implementation was removed.

## Removed Components

- `apps/cli`, `apps/server`, and the old `apps/web`
- task scheduler, locks, worktree runner, and repository analyzer packages
- connected-client queue, claim/finish HTTP endpoints, and MCP bridge
- `.scopeguard/tasks` verification scripts and v0.4 workflow documentation

The source remains recoverable from the `v0.4.1` Git tag.

## Data Compatibility

There is no automatic migration from v0.4 `.scopeguard` task files into Agent
Threads. Those records represent planned work rather than conversation
history, and importing them silently would create misleading state.

Keep any existing `.scopeguard` directory until its historical task records are
no longer needed. It is ignored by Desktop v2.

Desktop v2 stores application state in Electron's per-user application data
directory. SQLite contains Projects, profiles, Threads, messages, Runs, tool
records, approvals, and context revisions. Provider keys are held separately
by the encrypted SecretVault.

## Runtime Migration

- Direct or relay model access becomes a Provider Profile.
- A reusable executor configuration becomes an Agent Profile.
- Each independent stream of work becomes a Thread.
- Reviewed facts and decisions belong in Project Context.
- Local command-line agents use the optional CLI adapter and do not restore the
  v0.4 scheduler or task lifecycle.

## Rollback

Desktop v2 does not modify v0.4 task files. To run the old product, use a
separate checkout at the `v0.4.1` tag. Do not point both versions at the same
application data directory.
